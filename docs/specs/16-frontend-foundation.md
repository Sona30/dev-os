# 16 — Frontend Foundation: Shell, Routing, Design Tokens, Shared Components, Accessibility

**Covers:** EDD §5, §11; PRD s5 usability/compliance, WCAG 2.1 AA; `docs/design.md`. **Depends on:** 01. Stage 3 (`/frontend-setup`) scaffolds this; Stage 4 builds features on it. **All UI code must follow `docs/design.md` (`/design-system` skill).**

## 1. Project setup
- `create-next-app` 14 (App Router, TypeScript, Tailwind, ESLint, `src/` dir, alias `@/*`).
- Dependencies per spec 00 §2. Scripts: `dev`, `build`, `start`, `lint`, `typecheck`, `test`, `test:integration`, `test:e2e`, `eval`, `kb:build`, `kb:sync`, `agent:sync`, `prompts:schemas`, `seed:catalog`, `check:secrets`.
- `next.config.js`: `reactStrictMode`, security headers (`Strict-Transport-Security`, `X-Content-Type-Options`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: camera=(self)`, CSP with `script-src 'self'` + nonce, `img-src 'self' blob: data: https://*.supabase.co`, `connect-src 'self' https://*.supabase.co`, `frame-ancestors 'none'`), `images.remotePatterns` for Supabase Storage, webpack/worker config for `pdfjs-dist`.
- `netlify.toml`: `@netlify/plugin-nextjs`, functions dir `netlify/functions`, scheduled functions (spec 04), headers, `NODE_VERSION=20`.

## 2. Design tokens
`src/styles/tokens.css` is generated by `npm run tokens` from `docs/design.md` (semantic tokens only: `--color-bg`, `--color-surface`, `--color-text`, `--color-text-muted`, `--color-primary`, `--color-primary-hover`, `--color-border`, `--color-success`, `--color-warning`, `--color-danger`, spacing 4 px grid, radii, type scale). Tailwind `theme.extend` maps to these CSS variables; **no raw hex values or arbitrary spacing in components** (ESLint rule `no-restricted-syntax` on hex literals and `[…px]` arbitrary classes). Reference the primitive palette only inside the token file. Typography classes from the design system; body ≥ 16 px; Letter/A4 PDF uses its own token file `lib/pdf/layout.ts` (14 pt+).

## 3. Routing and layouts
Route map and groups exactly as EDD §5.2:
```
src/app/
  layout.tsx                  # fonts, providers (QueryClient, Supabase auth listener, Toaster)
  (marketing)/page.tsx
  (auth)/login|signup|forgot-password|reset-password/page.tsx
  auth/callback/route.ts
  (app)/layout.tsx            # AuthGuard + AppShell
  (app)/children/page.tsx
  (app)/children/[childId]/layout.tsx   # ChildShell: header, Stepper, tabs
  (app)/children/[childId]/{setup,plan,results,progress,settings}/page.tsx
  (app)/account/page.tsx
  pricing/page.tsx, privacy/page.tsx, terms/page.tsx, trust/page.tsx
  not-found.tsx, error.tsx, global-error.tsx
```
`ChildShell` computes the **current step** from data (no report → setup; confirmed report without worksheet → plan; worksheet ready/grading → results) and highlights the Stepper; every step remains navigable once its prerequisite exists; disabled steps show why ("Add your child's result first").

## 5. Shared UI components (`components/ui/`)
Button, IconButton, Input, NumberInput, Select, Checkbox, RadioGroup, Tabs, Dialog, Toast, Tooltip, Badge, **StatusBadge** (mastery labels: icon + text), Card, Table, Skeleton, Progress, Stepper, Alert (`role="alert"`/`status`), EmptyState, ErrorState (message + Try again), FileTile, ConfidenceBadge, GlossaryTerm. Each: variants via `class-variance-authority`, focus ring using the primary token, min touch target 44×44 px, documented props, Storybook is **not** used in MVP (a `/dev/ui` page behind `APP_ENV=local` lists variants).

## 6. UX state contract (applies to every data component)
Loading → skeleton (not spinner) with `aria-busy`; Empty → `EmptyState` with a single next action; Error → `ErrorState` with plain-language message, retry, and manual fallback where one exists; Success toasts for mutations; long jobs → `JobProgress`. Optimistic UI only for review confirmations.

## 7. Responsive and print
Mobile-first; breakpoints from the design system (640/768/1024/1280). Primary actions are bottom-anchored on mobile in the review queue and upload flows. Tables collapse to cards below 640 px. A `@media print` stylesheet for the worksheet preview hides chrome (the PDF is the canonical print artefact).

## 8. Accessibility (WCAG 2.1 AA)
- Landmarks (`header`, `nav`, `main`, `footer`), skip link, logical heading order, visible focus.
- Forms: labels bound to inputs, errors announced (`aria-live`/`aria-describedby`), no placeholder-only labels, `autocomplete` attributes.
- Contrast ≥ 4.5:1 (tokens validated by a test that reads `tokens.css` and checks pairs); status never conveyed by colour alone.
- Dropzone and review queue fully keyboard operable; `JobProgress` uses `aria-live="polite"`.
- Charts have text summaries and a table view; images have alt text (crops: "Handwritten answer for question N").
- `prefers-reduced-motion` respected; no autoplay.
- Language `lang="en"`; plain-language copy reviewed (reading level ≤ grade 8).
- Axe runs on every top-level route in CI.

## 9. Copy and tone guide (enforced by lint test)
Warm, concise, plain-spoken; define jargon on first use; "still building", "next step", "ready for more"; never "weak", "behind", "failing"; no score predictions; no claims that worksheets change an i-Ready score; the term "i-Ready" used descriptively with the non-affiliation footer.

## 10. Error boundaries and monitoring
`error.tsx` per segment shows `ErrorState` with a request id; client errors are POSTed (sanitised, no PII) to `/api/events` as `client.error` with the component name for triage.

## 11. Acceptance criteria
1. `npm run dev` serves the landing page; unauthenticated access to `(app)` redirects to login; `npm run build` passes with zero type errors.
2. Tokens file is generated from `docs/design.md`; a lint failure occurs when a component uses a hex literal.
3. Every route renders loading, empty and error states; verified by Playwright with forced failures.
4. Security headers are present on all HTML responses (header test).
5. Axe finds zero serious/critical violations on all top-level routes at 375 px and 1280 px.
6. Keyboard-only walkthrough of intake, review queue and download works (E2E).
7. Lighthouse accessibility score ≥ 95 on `/login`, `/children`, `/children/[id]/plan`.
8. The banned-words lint passes on all user-facing strings.
