# 15 — Testing Strategy and AI Evaluation Suite

**Covers:** PRD s10, s11 launch criteria, A1–A6, A11; EDD §13. **Depends on:** all feature specs. This spec defines test infrastructure, datasets, metrics and release gates; individual specs list their own cases.

## 1. Test pyramid and tooling

| Layer | Tool | Location | Runs |
|---|---|---|---|
| Unit | Vitest, fast-check | `tests/unit/**` | every PR |
| Integration | Vitest + Supabase CLI local stack (`supabase start`), MSW for Foundry | `tests/integration/**` | every PR |
| E2E | Playwright (desktop Chrome + mobile Safari/Chrome emulation), Foundry stubbed (`FOUNDRY_MOCK=true`) | `tests/e2e/**` | main branch + nightly |
| PDF/layout | Vitest + `pdfjs-dist` text extraction + image diff | `tests/unit/pdf/**` | every PR |
| Accessibility | `@axe-core/playwright` inside E2E | `tests/e2e/a11y/**` | main + nightly |
| AI evaluation | `tests/eval/**` runner (`npm run eval`) against real Foundry | nightly + on prompt/KB/model change | gate |
| Load / latency | k6 | `tests/load/**` | before beta, before each test window |
| Secrets check | `npm run check:secrets` | CI | every PR |

Coverage targets: ≥ 90% lines for `lib/calibration`, `lib/worksheets`, `lib/grading`; ≥ 80% for the rest of `lib/`; every route handler's every documented error code exercised at least once.

### Shared fixtures (`tests/fixtures/`)
`skills_catalog.dev.json` (spec 07), `foundry/*.json` (golden outputs per mode, plus invalid/edge variants), `reports/` (redacted sample reports as PNG/PDF), `sheets/` (photos of completed sample sheets incl. blurry/dark/partial), `seed/` (SQL seeding helpers for users, children, cycles), `names.json`.

### Local test environment
`supabase start` → apply `docs/specs/supabase-schema.sql` as migration `0001` → seed catalogue fixture → run Next.js with `.env.test` (Foundry mocked, rate limits on). Helpers: `createTestUser()`, `asUser(client)`, `seedCycleWithGradedItems()`.

## 3. AI evaluation datasets (ground truth, PRD s10)

| Dataset | Content | Size (minimum) | Labelling |
|---|---|---|---|
| `eval/reports/` | Redacted i-Ready Math reports, Grade 1 and 2, BOY/MOY/EOY, varied layouts, PDF and screenshot | 15 | Field values (window, score, placement, domains) by two reviewers |
| `eval/sheets/` | Photos of completed TestReady worksheets with names removed; includes messy handwriting, reversals, erasures, left-handed writers, poor lighting | 30 sheets / ≥ 300 items | Teacher/tutor SME transcribes each answer, correctness and error type |
| `eval/profiles/` | Simulated Child Profiles over 10–12 cycles (synthetic) | 20 | Generated by script with ground-truth rule outcomes |
| `eval/syllabus-review.md` | Educator ratings of gap tables and items | Rolling | Educator rubric |
Datasets live outside the repo (private storage) and are pulled by `scripts/eval-fetch.ts` using a read-only key; only synthetic fixtures are committed. Consent and de-identification recorded in `eval/DATASET_CARD.md`. **A segment tag per sheet** (handwriting style, device, lighting, grade) enables fairness cuts (PRD s11 Fairness).

## 4. Evaluations, metrics and release gates

| Eval | Method | Metric / target (Public Launch) | Beta gate | Cadence |
|---|---|---|---|---|
| E1 Report parsing | Field-level accuracy vs labels | overall score & placement ≥ 95%; domain results ≥ 90% | ≥ 90% / 85% | each release |
| E2 Gap mapping | Educator review of 20 diagnoses | ≥ 85% "appropriate"; 100% of skill ids in catalogue | same | each release |
| E3 Answer-key correctness | Generate 100 sheets, independent recomputation + ambiguity review | 100% correct, 0 ambiguous; 0 sheets shipped without `verified_at` | same | each release |
| E4 Math-level fidelity | Educator rating of item vs intended skill/level (sample 200) | ≥ 90% match | ≥ 85% | each release |
| E5 Reading-level fit | Automated readability (spec 08 §4.4) + educator spot check (50) | ≥ 90% of items in band | ≥ 85% | each release |
| E6 Freshness | 10 simulated cycles × 20 children | 0 repeated question hash / number set / context+structure within 4 cycles | same | each release |
| E7 Handwriting extraction | Per-item agreement with SME on ≥ 300 items | ≥ 92% exact; > 90% of errors flagged low-confidence | ≥ 88% | each release |
| E8 Confidence calibration | Reliability curve (10 bins) of confidence vs correctness | expected calibration error ≤ 0.10; tune `EXTRACTION_CONFIDENCE_THRESHOLD` | ≤ 0.15 | monthly + prompt change |
| E9 Grading agreement | System vs parent-confirmed (beta data) | > 90% | ≥ 85% | beta + monthly |
| E10 Error-type attribution | SME agreement on error type; `unclear` allowed | ≥ 75% | ≥ 65% | monthly |
| E11 Recalibration sanity | 20 synthetic 12-cycle profiles + property tests | 100% rule compliance (≤ 1 step, reading unchanged on math-only errors) | same | each release |
| E12 Latency | k6/real runs P95 per job | parse+diagnose ≤ 30 s, generate ≤ 90 s, grade ≤ 60 s (beta: ≤ 1.5×) | | each release |
| E13 Cost | 100 full cycles | avg ≤ $0.25; beta ≤ $0.35 | | monthly |
| E14 Fairness cuts | E7/E9 metrics by segment tag | No segment more than 8 points below overall; findings documented | document | monthly |
| E15 Safety content | 200 generated items scanned by denylist + educator spot check of 50 | 0 inappropriate items | same | each release |
| E16 Adversarial inputs | Non-iReady images, wrong subject, rotated, empty sheet, other child's sheet | 100% polite rejection / correct path (no fabricated scores) | same | each release |

Runner design (`tests/eval/run.ts`): loads dataset, calls the real pipeline functions (not HTTP) with service-role context against a throwaway Supabase schema, writes `EVAL_REPORT_DIR/<date>-<gitsha>/report.json` + `report.md` (metrics, failures with ids, cost, latency, model, prompt/kb versions). `npm run eval -- --suite=E3,E7` selects suites. CI gate script `scripts/eval-gate.ts` compares the report to thresholds in `tests/eval/thresholds.json` (stage-specific: `alpha`, `beta`, `launch`) and exits non-zero on failure.

### Evaluation spreadsheet (PRD s10)
`scripts/eval-export.ts` writes CSV with columns `Sheet_ID | Grade | Skill | Math_Level | Reading_Band | Expected_Answer | Child_Written | AI_Extracted | Extraction_Confidence | Match | SME_Error_Type | AI_Error_Type | Parent_Override | Notes` for SME review.

## 5. Production monitoring tie-in
Nightly regression subset (E3 with 20 sheets, E7 with 50 items, E11) on production configuration; weekly drift check samples 10 parent-overridden items; monthly educator audit of 10 random worksheets (PRD s10). Failures raise the alerts in spec 14.

## 6. Launch-stage checklists (PRD s11)

| Stage | Entry criteria verified by this suite |
|---|---|
| Internal Alpha | Intake→gaps→worksheet works E2E; no crashes on 10 sample reports; answer keys 100% verified (E3); disclosure present |
| Measurement Beta (≤ 50 households) | E7 ≥ 88%, E9 ≥ 85%, override ≤ 15%, latency ≤ 1.5×, cost ≤ $0.35, privacy review passed, 0 wrong-key incidents unflagged |
| Public Launch | All "launch" thresholds met; legal review complete; deletion flow tested (X1/spec 13); payments tested (Phase 2); seasonal load test passed |

## 7. Load test (`tests/load/cycle.js`, k6)
Scenario: 100 concurrent virtual users each running diagnose → generate → grade with the **mocked** Foundry (measures our platform: DB, jobs, Netlify) and a smaller real-Foundry run (10 concurrent) to measure quota/latency. Pass: error rate < 1%, P95 within targets, no job stuck > 10 min, DB connections within pooler limits. Repeat before each BOY/MOY/EOY window at 1.5× expected peak.

## 8. Acceptance criteria
1. `npm test`, `npm run test:integration`, `npm run test:e2e` pass on a clean checkout with only `supabase start` and mocks.
2. X1–X10 exist and pass; CI fails if any is removed (tagged `@critical`).
3. `npm run eval` produces a report and `eval-gate` correctly passes/fails against `thresholds.json` (verified with a deliberately degraded fixture).
4. Thresholds in `thresholds.json` match the table in §4.
5. Fairness segmentation appears in every E7/E9 report.
6. Dataset card documents consent and de-identification; no raw child data is committed.
